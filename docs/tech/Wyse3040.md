Wyse 3040是一款戴尔在2017年(左右)发布的，面向于企业的瘦客户机。搭载了英特尔的阿童木处理器，在性能上极其羸弱，运行Windows 10都十分费力。 

那么是什么原因，让我选择了这台瘦客户机呢？ 

答案只有一个：相对其他瘦客户机或者1L小主机来说，这款机器的性价比更高。<span class="spoiler">其实主要是因为这款机子内存硬盘都是板载的，不需要单独购买内存条和硬盘，在存储价格大幅度上涨的今天这是独一无二的选择了(泪)</span> 

这就得先交代一下购买主机的动机了：入坑弱电和服务器后，我对一台Linux主机的需求逐渐增大。这台主机并不需要用来运行高性能的业务，更多时候是用来安装Docker跑一些不吃性能的小业务。 

虽然Windows也能跑Docker，但是在我尝试过后发现：Docker Desktop的运行效果实在是没有Linux环境下好，还时常会出现一些奇奇怪怪的兼容性问题。 

由于在此之前购买的铭凡小主机被我安装了Windows 11作为宿主系统且使用了相对较长的一段时间，因此难以重装回Linux<span class="spoiler">(万恶的历史遗留问题)</span>。 

所以，我需要在性能够用的前提下，用尽可能低的价格，购买到一台可靠的小主机来运行Linux。 

在经过<del>询问AI</del>精挑细选后，我最终选择了这台Dell Wyse 3040。 

<img src="https://caihsicloud.oss-cn-guangzhou.aliyuncs.com/BlogsPicture/tech/Wyse3040/%E5%B1%8F%E5%B9%95%E6%88%AA%E5%9B%BE%202026-09-28%20213537.png" width=500>

**它的优势主要有三：**

- 内置板载内存、硬盘，无需另外购买，而且闲鱼上拥有大批量扩容机器售卖，可以很轻松地用相对较为低廉的价格购买到拥有充足存储容量的机型。 

- 体积小巧，外观优雅。机器只有巴掌大小<span class="spoiler">，在我退货时，快递员甚至认为我寄的不是电脑，是电脑配件（至于为什么退货请见后文）</span>，机身设计也十分简洁优雅。在同价位中，这台主机可能不是用料最好的，但是大概率是机身设计最好看的。同时，还采用被动散热，运行起来完全没有噪音。 

- 戴尔。没错，戴尔。起码是大品牌，比起淘宝上那些不知品牌的工控机买起来更让人安心。 

在敲定方案后，我购买了扩容的Wyse 3040，并为了稳定性加钱购买了戴尔原装的电源适配器。


## 机器概览

戴尔 Wyse 3040搭载了一颗 **Intel Atom X5 Z8350 @1.44GHz**，整机功耗仅2~3W (甚至不如一台手持小风扇功率高)

原生板载了 **2GB DDR3 RAM+8GB EMMC ROM**，我在闲鱼上购买的是扩容到128GB的版本。

机身搭载一个千兆网口、三个USB2.0、一个USB3.0(速率应该是5Gbps)

长宽高仅为 **101.6×101.6×27.94 毫米**，重量仅为 **240克**。三围小巧得不像电脑、重量轻得像是一台手机 

<img src="https://i.dell.com/is/image/DellContent/content/dam/ss2/product-images/dell-enterprise-products/cloud-client-computing/wyse/3040/pdp/ccc-wyse-3040-thin-client-pdp-4.jpg?fmt=jpg" width=500>

不过，这么小的体积虽然让整机优雅而小巧，却带来了很严重的拓展性问题：机器内部没有任何拓展接口，只为无线网卡预留了一个miniPCIE。

然而，这个miniPCIE接口走的协议却是SDIO协议。这也就基本上堵死了任何从机器内部直接拓展存储的可能。

<img src="https://static.chiphell.com/forum/202410/10/150521wymp24aa4davljy2.png" width=500>

因此，我在购买的时候特地选择了拓展至128GB的版本，这样的冗余基本可以支持我随便折腾这台瘦客户机了。

在适配器方面，我在闲鱼找了不少商家。基本上购买Wyse 3040时基本上都只是附赠一个12V 1A或1.5A的适配器，利用机器的宽电压兼容来进行供电。

不过为了机器的稳定，我最终找到了一个(据说)原装的5V 3A适配器，面前工作一切正常。

## 第一次开箱使用

<span class="spoiler">不对，我为什么要说是第一次</span>

在拿到机器后，我兴冲冲地在[@CatTom](https://blog.cattom.site)的指导下，完成了 Debian 13 的安装程序。

按照<mark>**正常情况**</mark>，此时只需要重启并拔出安装介质，就可以进入 Debian 13 了

不过很明显，这一切都开始变得很不正常起来

## **<span style="color: red;">No bootable devices</span>**

<span class="spoiler">天啊这是地狱吗</span>

正在我兴冲冲的看着 Debian 安装程序完成安装，按照要求拔出安装介质并重启系统后，一行提示就这样显示在了屏幕上

``` Bash

No bootable devices
```

同时，在 Pre-boot System Assessment 页面中，检测到了故障 **No Hard Drive detected**

<img src="https://caihsicloud.oss-cn-guangzhou.aliyuncs.com/BlogsPicture/tech/Wyse3040/IMG_20260928_212300.jpg" width=500>

在经历了各种尝试、查找了一堆网页、询问了AI很久，重装了不下十次系统，甚至是重装为 Ubuntu 24.04 都没有任何办法解决找不到引导程序的问题后，我最终决定**放弃**。

我在此后咨询了卖家，卖家表示他在扩容好后，都会进入PE格式化硬盘再发货。而巧的是：我也曾抱着死马当活马医的心态进入过PE系统。

奇迹的内容就在于：无论是在系统安装程序还是在PE系统内，硬盘都能被成功识别。这也就是为什么卖家在PE系统格式化硬盘的时候没有发现任何问题。

然而，在BIOS中无论如何也依然检测不到硬盘。

<img src="https://caihsicloud.oss-cn-guangzhou.aliyuncs.com/BlogsPicture/tech/Wyse3040/IMG_20260928_212825.jpg" width=500>

于是在与卖家说明情况后，我将小主机寄回给卖家进行检测。

在退回小主机后，虽然卖家什么都没有回复，不过同意退款以及退运费这两个操作应该证明这台主机的硬盘确实出现了问题。

## 再次尝试

不信邪的我再次购买了相同配置的主机，再次进行系统安装。

在完成了安装程序的所有操作后，我心怀忐忑地按照程序要求，重启主机、拔出安装介质

终于，奇迹发生了：

<img src="https://caihsicloud.oss-cn-guangzhou.aliyuncs.com/BlogsPicture/tech/Wyse3040/IMG_20260928_214227.jpg" width=500>

**好消息：** 系统终于成功被引导，经过加载后，成功进入了 Debian 系统主界面

**坏消息：** 锟斤拷烫烫烫

<img src="https://caihsicloud.oss-cn-guangzhou.aliyuncs.com/BlogsPicture/tech/Wyse3040/IMG_20260928_214643.jpg" width=500>

初步经过初步推测，应该是系统没有中文字库导致的问题。于是我按照网上的教程，将系统语言更改回了英文。

此外，这台电脑还出现了在开机过程中产生一大堆bash报错的问题：

<img src="https://caihsicloud.oss-cn-guangzhou.aliyuncs.com/BlogsPicture/tech/Wyse3040/IMG_20260928_214933.jpg" width=500>

而且无论输入命令 **poweroff**、**reboot** 等，都会报错：

``` bash

bash: poweroff: command not found
bash: reboot: command not found
```

经过<del>询问AI</del>一番排查，我最终<span class="spoiler">用最直白、最不绕弯子的方式</span>确定了：因为 root 用户的 PATH 环境变量没有包含 /sbin 和 /usr/sbin 目录，导致系统管理命令无法被找到。

在按照AI的指导操作后，我最终成功解决了这个问题。
